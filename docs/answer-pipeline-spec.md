# 정답·해설 생성 파이프라인 — 분석 및 명세

작성일 2026-08-26 · 대상 데이터 `dump.js` (684문항) · 상태 **명세 (미구현)**

## 0. 결론

**가능하다. 단, "LLM에 문제를 넣고 답을 하나 받는" 방식으로는 안 된다.**

단일 호출 방식은 자신이 틀렸을 때도 자신 있게 답한다. 그러면 지금 문제가 되는 외부 답안(크라우드 투표)의 결함을 다른 종류의 결함으로 갈아끼우는 것에 불과하다. 대신 **답을 내는 단계와 답을 검증하는 단계를 분리하고, 검증을 통과한 정도에 따라 문항에 신뢰 등급을 붙여** 학습자가 "이건 확정, 이건 논쟁 중"을 구분할 수 있게 해야 한다.

측정 근거(§2, §3)에 따른 예상 결과:

| 등급 | 정의 | 예상 비중 |
|---|---|---|
| **A 확정** | 독립 시행 만장일치 + 공식 문서 근거 + 반증 실패 | 75~80% |
| **B 유력** | 다수결 우세 + 문서 근거 | 12~18% |
| **C 논쟁** | 표가 갈림 또는 반증 성공 → 양측 논거 병기 | 5~10% |
| **D 결함** | 정답이 될 수 있는 선택지가 없는 문항 | 1~3% |

핵심은 **D와 C를 A로 위장하지 않는 것**이다. 외부 답안의 진짜 문제는 오답률 자체가 아니라, 오답에도 "정답"이라는 라벨이 붙어 있어 학습자가 틀린 것을 외운다는 점이다.

## 2. 파일럿 실측 — 문항의 모호성 구조

무작위 24문항(seed 7, 단일 18 / 2택 4 / 3택 2)을 실제로 풀어 분류했다.

| 분류 | 건수 | 비중 |
|---|---|---|
| 구조적으로 명확 — 정답이 하나로 결정됨 | 19 | 79% |
| 논쟁 가능 — 합리적으로 다른 답을 고를 수 있음 | 4 | 17% |
| **문항 자체 결함** — 완전히 옳은 선택지가 없음 | 1 | 4% |

**중요한 한계:** 이 파일럿은 내 답의 *정확도*를 측정한 것이 아니다(채점할 정답지가 없다). 측정한 것은 **문항의 모호성 분포**, 즉 "몇 %가 애초에 논쟁 없이 결정되는가"다. 이 값이 등급 A의 상한을 정한다.

### 대표 사례

**명확 (19건 유형)** — #470 "IPv6, 외부에서 들어오는 연결은 차단" → egress-only internet gateway. 다른 선택지가 요구사항을 물리적으로 만족하지 못한다. 이런 문항은 어떤 방식으로 풀어도 같은 답이 나온다.

**논쟁 (#520)** — DynamoDB, "트래픽 예측 불가" + "읽기/쓰기 처리량 중간~높음", 최저 비용.
- 예측 불가 → 온디맨드(B)
- 처리량이 지속적으로 중간~높음 → 프로비저닝+오토스케일링(A)이 실제로 더 싸다

두 근거가 서로를 상쇄한다. 이런 문항은 정답을 하나 박아두면 반드시 일부 학습자를 잘못 가르친다. **양측 논거를 병기하고 "시험에서는 예측 불가 키워드에 온디맨드로 답하라"는 실전 지침을 따로 주는 것이 정직하다.**

**결함 (#108)** — "RDS 데이터가 갱신될 때" 여러 대상 시스템에 전파. 통상 정답은 D(RDS 이벤트 알림 → SNS 팬아웃 → SQS). 그런데 **RDS 이벤트 알림은 인스턴스 수준 이벤트용이며 행 단위 데이터 변경을 트리거하지 않는다.** DynamoDB Streams에 해당하는 기능이 RDS에는 없다. A·B의 "DB 갱신 시 Lambda 트리거"도 마찬가지로 성립하지 않는다. **완전히 옳은 선택지가 없다.** 이 사실을 설명해주는 것이 답을 하나 찍어주는 것보다 학습 가치가 높다.

## 3. 외부 근거

### 3.1 크라우드 답안의 신뢰도 — 사용자 관측이 맞다

ExamTopics 계열 답안은 커뮤니티 투표로 결정되며 댓글에서 자주 반박된다. 답을 그대로 믿지 말고 토론을 비판적으로 읽으라는 것이 일반적 권고다. **"답이 부정확하고 설명이 부족하다"는 평가는 근거가 있다.**

### 3.2 LLM의 이 시험 수행 능력

- 2023년 GPT-4: SAA에서 **700/1000점, 합격선 720 미달(불합격)**. 같은 모델이 상위 자격인 SAP에서는 832점 합격 — 측정 방법에 따라 편차가 크다는 뜻이다.
- 2026년 프론티어 모델(Claude Opus 5 / Fable 5 등)은 HLE 등 추론 벤치마크에서 당시 대비 압도적이지만, **SAA-C03에 대한 공개 벤치마크는 존재하지 않는다.**

→ **"요즘 모델이면 잘하겠지"로 넘어가면 안 된다. §6의 캘리브레이션으로 직접 측정해야 한다.**

### 3.3 다수결·자기일관성이 이 작업에 특히 잘 맞는다

자기일관성(self-consistency)은 여러 추론 경로를 표집해 다수결하는 기법으로 GSM8K +17.9pp, AQuA +12.2pp 등의 향상이 보고되었다. 순위투표(ranked voting)는 단순 다수결을 추가로 상회하며, 적응적 표집은 표본 수를 최대 7.9배 줄인다.

이 계열 기법의 알려진 제약은 **"정답을 정확히 일치 비교할 수 있는 과제에만 적용 가능"** 이라는 점인데, 4~6지선다는 정확히 그 조건을 만족한다. 즉 **이 작업은 다수결 검증이 가장 잘 통하는 형태의 과제다.**

### 3.4 문서 근거 확보 수단이 존재한다

`awslabs/mcp`의 **AWS Documentation MCP Server**가 공식 검색 API 기반 문서 검색·마크다운 변환·표 검색을 제공한다. 해설의 각 주장을 공식 문서 URL에 묶을 수 있다 → 환각 인용을 기계적으로 검출할 수 있다(§5 Stage 2).

## 4. 등급 체계

```
A 확정  독립 5회 만장일치 ∧ 문서 근거 확보 ∧ 반증 실패 ∧ 셔플 불변
B 유력  4/5 또는 3/5 다수 ∧ 문서 근거 확보 ∧ 셔플 불변
C 논쟁  표 분산 ∨ 반증 성공 ∨ 셔플 시 답 변동 → 양측 논거 병기
D 결함  모든 선택지에 대해 반증 성립 → 문항 결함 자체를 설명
```

**셔플 불변성 검사**가 이 설계에서 가장 값싸고 강한 검증이다. 선택지 순서를 뒤섞어 다시 물었을 때 다른 답이 나오면, 그 답은 내용이 아니라 위치에 반응한 것이다. 이미 모의고사 쪽에서 정답 B 편중을 셔플로 해결한 바 있는데(`withShuffledOptions`), 같은 원리를 검증 도구로 재사용한다. 비용은 시행 1회 추가뿐이다.

## 5. 파이프라인 명세

```
Stage 0  정규화        도표 이미지 첨부, select N 명시, 선택지 letter 부여
   ↓
Stage 1  독립 해답 ×5  서로의 결과를 못 보게 분리 실행 (temperature > 0)
   ↓                  출력: answer[], 근거 요지, 자기확신도
Stage 2  문서 검증     최다득표 답의 근거 주장별로 AWS 공식 문서 URL 확보
   ↓                  → 인용 URL을 실제로 fetch해 주장이 문서에 있는지 확인
Stage 3  반증          상위 2개 후보 각각에 "이 답이 틀렸음을 논증하라" 지시
   ↓                  기본값을 "반증 성공"으로 두어 회의적으로 판정
Stage 4  셔플 불변성   선택지 순서를 바꿔 Stage 1 재시행 1회, 답 일치 확인
   ↓
Stage 5  등급 판정     §4 규칙 적용 (기계적, 모델 재량 없음)
   ↓
Stage 6  해설 생성     A/B/C/D 등급별 서식 (§7), 한국어 + 영어
   ↓
Stage 7  외부 답안 대조 사용자가 답안 파일 확보 시 diff 리포트 — 절대 자동 덮어쓰기 금지
```

### 설계 원칙

**Stage 1은 반드시 서로 격리한다.** 같은 대화에서 5번 물으면 첫 답에 끌려간다(앵커링). 독립 요청으로 보내야 표가 의미를 가진다.

**Stage 2는 인용을 검증한다.** 모델이 URL을 그럴듯하게 지어내는 것이 이 파이프라인의 최대 위험이다. 인용된 URL을 실제로 가져와 해당 주장이 그 페이지에 존재하는지 확인하는 단계를 자동화한다. 확인 실패 시 등급을 한 단계 내린다.

**Stage 3의 기본값은 유죄 추정이다.** "이 답이 맞는지 확인하라"고 물으면 모델은 동의하는 쪽으로 기운다. "틀렸음을 논증하라, 확신이 없으면 반증 성공으로 판정하라"로 방향을 뒤집어야 검증이 작동한다.

**Stage 5는 코드가 판정한다.** 등급을 모델이 스스로 정하게 하면 자기 확신도를 낙관적으로 보고한다. 투표 결과·검증 통과 여부라는 관측값만으로 결정론적으로 계산한다.

**Stage 7은 병합하지 않는다.** 외부 답안이 도착하면 우리 결과를 덮어쓰는 것이 아니라 **대조표**를 만든다. 불일치 항목이야말로 가장 학습 가치가 높은 지점이다(둘 중 하나는 틀렸고, 그 이유가 곧 시험 포인트다).

## 6. 캘리브레이션 게이트 (필수 선행)

**전량 실행 전에 정확도를 실측해야 한다.** 정답을 알고 있는 문항으로 등급 A의 실제 정확도를 측정한다.

검증 집합 후보:
1. AWS 공식 샘플 문항 / AWS Skill Builder 공식 practice question set (권위 있는 정답 보유)
2. `data.js`의 큐레이션 16문항 (정답·해설 보유, 단 출처 검증 필요)
3. 공식 문서에서 정답이 일의적으로 도출되는 문항 (수동 선별 30문항 내외)

**게이트 조건**

| 측정값 | 조치 |
|---|---|
| 등급 A 정확도 ≥ 97% | A를 "확정"으로 노출 |
| 90~97% | A를 "유력"으로 강등 표기, 전량 진행 |
| < 90% | 파이프라인 재설계. 전량 실행 금지 |

이 게이트가 없으면 §0의 예상 비중은 추측에 불과하다.

## 7. 데이터 스키마

`dump.js`는 생성물이므로 손대지 않는다. 정답·해설은 **별도 파일 `answers.js`** 로 분리해 재생성 가능성을 보존한다.

```js
const SAA_ANSWERS = {
  "saa001": {
    answer: [2],                    // 선택지 인덱스 배열 (select N개)
    tier: "A",                      // A | B | C | D
    votes: [0, 0, 5, 0],            // Stage 1 득표 분포
    shuffle_invariant: true,        // Stage 4 결과
    refuted: false,                 // Stage 3 결과

    rationale_ko: "...",            // 정답 근거
    distractors_ko: [               // 오답별 탈락 이유 (전 선택지)
      { i: 0, why: "..." }, ...
    ],
    exam_point_ko: "...",           // 시험에서 이 문항이 무엇을 보는가
    dispute_ko: null,               // 등급 C일 때 반대 논거
    defect_ko: null,                // 등급 D일 때 문항 결함 설명

    sources: [                      // Stage 2에서 fetch 검증된 URL만
      { url: "https://docs.aws.amazon.com/...", verified: true }
    ],
    concepts: ["vpc-endpoint", "dynamodb"],   // knowledge.js 노드 id — 마인드맵 연결
    currency_note_ko: null,         // §1.4 구식 표기 안내

    model: "claude-opus-5",
    generated_at: "2026-08-27",
    external_key: null,             // Stage 7: 외부 답안 (도착 후 기입)
    external_agrees: null           // 일치 여부
  }
}
```

`concepts` 필드로 이미 존재하는 95개 개념 그래프에 연결되므로, 해설에서 마인드맵 노드로 점프하는 동선이 추가 작업 없이 생긴다.

## 8. 비용·시간 추정

문항당 토큰 추정: 입력 ~5,000 (문제 + 시스템 프롬프트 캐시 + 문서 컨텍스트), 출력 ~7,000 (해답 5회 + 반증 2회 + 셔플 1회 + 해설 한/영).

Batch API는 입출력 모두 50% 할인, 프롬프트 캐시 적중은 기본 입력가의 10%. 684문항 전량 기준:

| 구성 | 입력 | 출력 | 합계 |
|---|---|---|---|
| Opus 5 전량 (batch) | 3.42M × $2.50 = $8.6 | 4.79M × $12.50 = $59.9 | **≈ $69** |
| Sonnet 5 전량 (batch) | 3.42M × $1.00 = $3.4 | 4.79M × $5.00 = $24.0 | **≈ $27** |
| 혼합 — Sonnet 5로 해답·셔플, Opus 5로 반증·논쟁 판정 | | | **≈ $35** |

웹 검색을 쓰면 $10/1,000회가 추가되나, 문서 조회는 MCP 문서 서버(§3.4)로 대체하면 토큰 비용만 든다. 프롬프트 캐시로 시스템 프롬프트를 재사용하면 입력 비용은 표보다 더 내려간다.

**결론: 전량 처리 비용은 $30~70 수준이고, Batch API로 24시간 내 완료된다.** 비용은 이 프로젝트의 제약이 아니다. 제약은 정확도 검증이다.

**권장:** 혼합 구성. 단, §6 캘리브레이션은 Opus 5 전량 구성으로 먼저 측정해 상한을 확인한 뒤 저비용 구성으로 내려가며 성능 손실을 본다.

## 9. UI 명세 (기존 앱 통합)

덤프 브라우저(`app.js` 문제 뷰)에 추가:

- **정답 표시 + 등급 배지** — 확정 / 유력 / **논쟁** / **결함**. 등급별 색으로 구분하고, 논쟁·결함은 눈에 띄게 한다.
- **해설 아코디언** — 정답 근거 → 선택지별 탈락 이유 → 시험 포인트 → 검증된 출처 링크
- **논쟁 문항** — 양측 논거를 나란히 배치하고, 하단에 "실전에서는 이렇게 답하라" 지침을 별도로 둔다. 이것이 논쟁 문항의 핵심 가치다.
- **결함 문항** — "이 문항에는 완전히 옳은 선택지가 없다"를 명시하고 왜인지 설명. 정답을 억지로 하나 고르게 하지 않는다.
- **개념 링크** — `concepts` 필드로 마인드맵 해당 노드로 점프
- **최신성 안내** — §1.4 해당 문항에 "시험 표기 X = 현행 Y" 배너
- **신고 버튼** — 해설이 틀렸다고 판단되는 문항을 로컬에 기록. 등급 A가 실제로 틀린 경우를 잡는 마지막 안전망.
- **외부 답안 대조 뷰** — Stage 7 diff. 일치/불일치/우리가 논쟁으로 표시한 항목을 분리해 보여준다.

**모의고사 확장:** 등급 A/B 문항이 확보되면 현재 16문항인 시험 시뮬레이터를 실제 65문항 구성으로 확장할 수 있다. 등급 C/D는 모의고사에서 제외하고 학습 모드에만 노출한다.

## 11. 실행 계획

| 단계 | 범위 | 산출물 | 상태 |
|---|---|---|---|
| **P0** | 24문항 모호성 구조 파일럿 | §2 분포 (79/17/4) | ✅ 완료 |
| **P1** | 캘리브레이션 집합 30~50문항 구축 | 권위 있는 정답지, 등급 A 정확도 실측 | 대기 |
| **P2** | 파이프라인 구현 + 100문항 시행 | `scripts/answer.py`, 등급 분포 실측, 게이트 판정 | 대기 |
| **P3** | 684문항 전량 batch | `answers.js` | 대기 |
| **P4** | UI 통합 | 해설 뷰, 등급 배지, 논쟁·결함 표시 | 대기 |
| **P5** | 외부 답안 도착 후 대조 | diff 리포트, 불일치 문항 재심 | 답안 파일 확보 후 |

### 진행 중인 번역 작업과의 병합 권고

현재 `dump-ko.js`에 40/684 문항이 번역되어 있고, 남은 644문항을 빈출 순으로 번역하는 작업이 대기 중이다. **번역과 해설 생성을 하나의 패스로 합치는 것을 권한다.**

- 문제 본문을 이미 컨텍스트에 넣은 상태에서 해설을 생성하므로, 따로 돌릴 때보다 입력 토큰이 절반 든다
- 번역 품질도 올라간다 — 정답과 근거를 알고 번역하면 기술 용어 선택이 정확해진다(예: 오답 선택지의 미묘한 함정 표현)
- 순서: **P1·P2를 먼저 끝내고**(정확도 게이트 통과 확인), P3에서 번역과 해설을 동시 생성

즉 **번역 작업을 재개하기 전에 P1·P2를 수행하는 것이 총 비용과 품질 양쪽에서 유리하다.**
